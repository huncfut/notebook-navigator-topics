# Notebook Navigator Topics native integration

Proposed revision for [issue #1](https://github.com/huncfut/notebook-navigator-topics/issues/1). The source map is for Notebook Navigator `3.5.1` at commit `44215001884fa57351e6eb387355fbe5eb660975`. The feature scope is defined in [PLAN.md](PLAN.md).

## Upstream code map

| Area | Notebook Navigator 3.5.1 | Integration point |
| --- | --- | --- |
| Left navigation data | `useNavigationPaneTreeSections` flattens folders, tags, and properties into `CombinedNavigationItem` rows. `useNavigationPaneData` and `useNavigationPaneItemPipeline` assemble and decorate them. | Supply topic rows to the same pipeline. Each occurrence needs a key based on its section and ancestor chain so two branches can expand independently. |
| Left navigation rendering | `NavigationPaneLayout` renders the virtualized tree through `NavigationPaneItemRenderer` and `NavigationPaneTreeRow`. Real folders render through `FolderItem`. The Tags and Properties roots use `VirtualFolderComponent` from `VirtualFolderItem.tsx`. | Reuse `VirtualFolderComponent` for the Topics group and section headings. Extend that row's presentation for selectable topic nodes with the existing folder-note name styling and native context and trailing actions. Preserve the existing chevron, indent guides, count, selection, and theme classes. |
| Selection and interaction | `SelectionContext` publishes the selected folder, tag, or property. `useNavigationPaneTreeInteractions` dispatches selection, applies auto-expansion, and chooses the active pane. `useNavigationPaneKeyboard` and `useNavigationPaneScroll` consume the shared rows and selection. | Add a topic selection to the shared state and route row clicks, chevrons, and keyboard gestures through the native handlers. Use the chosen occurrence for focus, scrolling, and ancestry. Use the section and note for file membership and hiding across occurrences. |
| Folder-note clicks | `FolderItem` separates name clicks from row clicks. `useNavigationPaneTreeInteractions` looks up the folder note and resolves modifier behavior with `resolveFolderNoteClickOpenContext`. `openFolderNoteFile` delegates new-context opens to `openFileInContext`. | Use the same name and row interaction pattern with the topic's real `TFile`. Reuse Navigator's opener and modifier logic for current-tab and new-tab behavior. `FolderItem` reads a real `TFolder` and exposes folder mutation actions, so virtual topics fit the virtual row component. |
| Right-pane data | `getFilesForNavigationSelection` dispatches to the appropriate file finder. `useListPaneData` builds the list from the returned `TFile` objects and feeds native refresh, grouping, and search. `fileFinder.ts` already applies profile and hidden-file rules to path-based collections. | Resolve each topic's direct leaf paths through the same scoped visibility and ordering logic used by the existing file finders. A selected topic with zero eligible notes supplies an empty list. Topic graph changes refresh the native list while a topic is selected. |
| Right-pane rendering | `ListPane` owns `ListPaneHeader`, `ListPaneTitleArea`, `SearchInput`, and `ListPaneVirtualContent`, which renders `FileItem`. | Supply the topic title, breadcrumb, and list scope to the existing hooks. The native list then supplies previews, pills, sorting, grouping, context menus, multi-select, and keyboard behavior. |
| Search and filtering | `useListPaneSearch` debounces queries and parses Navigator's filter tokens. `filterListPaneFiles` applies them to `baseFiles`. Tag and property gestures can update the live query. The optional Omnisearch pipeline intersects its hits with the same base-file paths. | Give search the topic's base file set before filtering. Preserve query behavior when navigating between topics and native scopes. Use path-set intersection for Omnisearch, since one topic can contain files from several physical folders. |

## Proposed changes

1. Replace the separate Topics tree and file list from `1b9e026` with an upstream navigation source and list scope. Keep the existing graph, configuration format, cycle repair, and version-matched installer. Retire the parallel selection state, replacement list, and duplicate browsing styles.
2. Add Topics to the existing item pipeline, expansion and selection handlers, and list title and scroll hooks. Keep the collapsible Topics group and section-level warnings. Use Navigator's Show hidden items preference to reveal hidden occurrences. A topic-name click opens its note and selects its direct leaves. A row click selects the list, and the chevron controls expansion.
3. Use `getFilesForNavigationSelection` as the shared boundary for topic file membership. Keep the approved direct-leaf behavior, including for empty topics. Feed normal file rows and search from that scope. Review code that assumes a physical folder, tag, or property so actions that require those targets do not acquire one when a topic is selected.

## Proposed follow-up for topic drops and search gestures

Navigator marks target rows with `data-drop-zone` and handles desktop drops in `useDragAndDrop`. Both tag and property drops use `getMarkdownFilesFromDragEvent` to resolve the dragged notes. Add a topic target to that same hook and use `VirtualFolderComponent`'s existing drop attributes. Resolve every occurrence of the same topic to one section and note target.

- Append the target link to the section's relationship property through `processFrontMatter`. Preserve existing links, skip duplicate links, and write the relationship and any required leaf metadata together. A note that already satisfies the leaf filter keeps its type. For an ineligible note, offer the matching leaf requirements when the filter has multiple alternatives. Apply a single unambiguous requirement automatically when it can be added without replacing an existing value. Skip conflicting values, nodes in the section, and ineligible file types with a clear result. Use the existing cycle and metadata refresh behavior.
- Route the configured search modifier through `getTagSearchModifierOperator` and the existing list search update path. Add a reversible `topic:` filter to Navigator's search syntax. Resolve its topic by section and note path, and evaluate it using the graph's direct leaf membership. This handles aliases, duplicate basenames, and sections that share a relationship property. Preserve the current folder, tag, property, or topic scope and existing query. Follow Navigator's AND and Shift-modified OR behavior.
- Verify single and multi-note drops, scalar and list relationships, duplicate drops, ambiguous and conflicting leaf requirements, and still-open lists refreshing after a drop. Verify toggling the search filter, combining it with existing filters, resolving repeated topic names, and the original tag and property gesture behavior.
